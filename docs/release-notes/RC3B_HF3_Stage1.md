# Enterprise V1.3 Phase 10 RC3-B HF3 Stage1

## Data Consistency / Repository 重構

- 新增 `assets/data-consistency-service.js`，集中計算原始訂單金額、加收費用、最新應收、期初已收、交易收款、退款、淨已收、剩餘應收與付款狀態。
- 訂單管理、入住管理、收款管理、Dashboard 與房務可共用同一組 selectors；不再以畫面快取作為金額來源。
- 訂單編輯的「已收金額」由統一 selector 回填，儲存時只反推 `openingPaid`，付款紀錄保持獨立且不重複計算。
- 入住清單依統一付款狀態自動核對「訂金」與「尾款」。
- Cloud Repository、Schema migration 與 Realtime 明確保存／還原 `openingPaid`，避免把衍生 `paid` 誤當期初已收。
- 房況日曆、首頁待辦、房態、通知與批次完成判斷只採計有效房務狀態；已完成及已取消的歷史任務不再顯示為清掃待辦。
- 每次成功推送後會局部拉取最新雲端 revision，避免下一次同步誤判版本衝突。
- 偵測到真正的 revision conflict 時，停止重送舊快照、重新拉取單一最新雲端狀態並自動解除該衝突，不再讓 Realtime 長期停在 error 或以阻斷式警告打斷目前頁面。
- 已退房但尚有剩餘應收的訂單，會在首頁營運提醒最前方以紅色「逾期未結清」卡片顯示住宿日期、未收金額、逾期天數及立即收款按鈕。
- 逾期未結清款同步建立 Critical 帳務通知並持續顯示，直到剩餘應收歸零；取消與 No Show 訂單不列入。
- 收款視窗的訂單選取值會跨局部更新及重新渲染保存，不再跳回第一筆訂單。
- 切換收款訂單會同步更新住宿日期、帳務摘要、剩餘應收與建議收款金額；欄位「日期」更名為「收款日期」，避免與住宿日期混淆。
- Realtime 衝突保護改為比較實際業務欄位；revision 較舊但內容完全相同的訂單快照會略過，不再阻擋同批新增收款。
- 新增收款可獨立寫入 payments；同步後再由 Single Source of Truth 回算已收淨額與剩餘應收，避免儲存後被雲端舊畫面覆蓋。
- 收款提交改為可驗證交易流程：防止重複送出、寫入後確認本機付款 ID 確實存在，再等待 Realtime 雲端同步結果。
- 本機或雲端寫入失敗會保留視窗並顯示實際錯誤；離線時明確提示已排入重試，不再無條件關閉視窗或回報假成功。
- 修正舊衝突佇列項目阻塞新收款：系統會逐筆清除失效快照、刷新 revision、繼續提交較新的付款項目，再回拉確認。
- 線上收款只有在雲端回讀仍找到同一 payment ID 時才顯示「收款已儲存」，避免畫面短暫顯示已結清但實際仍為部分收款。
- 修正真正阻擋 payments 的資料表順序：`order_rooms` 原先沒有指定複合唯一鍵，既有房間關聯會在 payments 之前造成 duplicate-key 中止。
- 雲端寫入順序改為 orders → payments → order_rooms，並為 order_rooms 使用 `order_id,room_id` conflict target；輔助關聯不再阻擋收款。
- Migration 匯入採用相同複合鍵規則；資料表寫入錯誤會回報實際 table 名稱。
- 收款正式改用專用 Cloud Payment Repository：只 upsert 本次 payment，不再透過包含 orders、order_rooms 等資料的整批 Realtime 快照。
- 付款寫入後直接從雲端 payments 表回讀並重建本機付款集合，再重新計算所有訂單的已收與剩餘；可阻止稍後背景回拉舊付款資料。
- 線上付款提交會略過該次整批 Realtime push；離線時才排入原有重試佇列。
- 逾期未結清改為嚴格依實際退房日期判斷：只有 `checkout < 今天` 才算逾期；未來日期即使狀態資料異常為已退房，也只顯示一般待收款。
- 訂單卡片收合標題新增住宿日期，桌機與手機不需展開即可查看入住～退房區間。
- 未結清逾期界線改為退房日 11:00（或訂單核准的延後退房時間）；當日超過期限即轉為逾期，不再等到隔日。
- 同日逾期顯示逾期小時數，超過一天後顯示逾期天數；首頁與通知中心共用同一 deadline selector。
- 訂單叫車日期預設帶入入住日期；入住日期變更時，尚未手動修改的叫車日期會同步更新。
- 首頁服務待辦改用集中 selector，會合併住宿服務與有效舊欄位；早餐或叫車已有安排內容時，即使舊資料缺少 service/date 也會補齊並顯示。
- 保留 RC3-B HF2 的 Cloud Status UI、局部更新、目前頁面、捲動位置及展開狀態。

## HF14

- 模板中心固定補齊入住須知、早餐通知、叫車通知、寵物入住須知、全館包棟與小包棟清單。
- 統一模板的本機與雲端資料格式，儲存及同步後仍可繼續編輯。
- 住宿服務保留並遞增雲端 revision，修正儲存後被舊資料覆蓋而消失。
- Cloud hydration 保留服務 revision、建立時間及更新時間。

## HF15

- 新增待同步住宿服務保護層，服務儲存後立即建立持久化 pending 紀錄。
- Realtime 拉取雲端資料時先合併 pending 服務，禁止舊雲端快照覆蓋剛儲存的內容。
- 僅在雲端回讀確認相同服務版本與內容後解除 pending 保護。
- 離線或雲端延遲時仍保留服務資料，等待後續同步。

## HF16

- 入住管理、收款管理與住宿服務卡片摘要新增完整入住～退房日期。
- 每個管理頁獨立保存捲動位置。
- 切換其他模組後返回，恢復原本展開的卡片與工作位置。
- 局部更新及雲端資料套用後維持目前頁面、卡片與捲動狀態。

## HF17

- 訂單剩餘應收為 0 時，有費用的住宿服務自動更新為「已收款」。
- 訂單結清時，尚未核帳的收款、尾款與加收費用自動更新為「已核帳」。
- 付款資料保留 verifiedAt、updatedAt 與 revision，避免同步後退回待核帳。
- 雲端資料套用後重新執行集中式結清核對，並將修正結果同步回雲端。

## HF18

- 入住人數改為可直接輸入的數字欄位，移除互相干擾的重複輸入處理。
- Repository 與 Cloud Migration 統一使用訂單 `count` 作為入住人數來源，並相容舊欄位。
- 編輯訂單時提高 revision，避免雲端舊快照在儲存後把入住人數覆蓋回舊值。
- 新增入住人數欄位、Repository 映射、Migration 映射與 revision 的靜態迴歸檢查。

## HF19

- 入住人數改用原生數字欄位，提供上下箭頭、鍵盤調整及最小一人的限制。
- 移除首次點擊時清空人數的行為，避免使用箭頭時原值消失。
- 明確區分「營運流程（作業進度）」、「訂單生命週期」及「訂單狀態（確認／付款）」的用途。
- 訂單操作按鈕分別標示「變更生命週期」與「作業」，降低狀態操作混淆。
- 房務人員卡片新增編輯功能，可修改姓名、群組、開始及結束時間；更名時同步更新既有房務指派。

## HF20

- 訂單編輯表單只保留「訂單生命週期」供人工操作，消除三組狀態下拉選單的重複與矛盾。
- 作業進度改由入住、退房與房務操作自動更新；付款狀態依實際收款自動計算，表單僅顯示系統摘要。
- 房務人員卡片新增刪除按鈕，採停用式刪除以保留歷史紀錄。
- 若房務人員仍承接進行中工作，系統會阻止刪除並要求先完成重新指派。

## HF21

- 修復未到入住日期卻顯示「已退房」、同時仍出現「作業：入住」的生命週期分裂問題。
- 加入日期防呆：未到入住日不可完成入住，未到退房日不可完成退房。
- 載入本機或雲端資料時，自動修復不可能的未來入住／退房狀態，並提高 revision 回寫雲端。
- 「完成入住」改由訂單生命週期連動：執行作業入住或在入住管理確認完成後，會同步設為已入住並自動勾選。
- 已入住或已退房後，不允許單獨取消「完成入住」，避免清單與訂單狀態再次分裂。

## HF22

- 將 HF21 的生命週期日期防呆、異常資料修復及完成入住連動完整套用至手機版共用資料流程。
- 手機訂單卡的生命週期／作業按鈕改為整列顯示，避免與一般功能按鈕混淆。
- 手機入住管理將「完成入住」獨立整列並加大觸控區，勾選後連動訂單生命週期。
- 手機編輯訂單的系統自動狀態摘要改為單欄排列，提升窄螢幕可讀性。

## QA

- 所有 JavaScript 檔案執行語法檢查。
- HTML 本機資源引用檢查。
- 測試 39,000 應收／19,000 已收／20,000 未收案例。
- 測試追加收款、退款、加收費用、全額結清及入住核對狀態。
- 驗證房況日曆不會把已完成或已取消任務重新標成清掃。
- 驗證版本衝突會移除失效佇列項目、刷新 revision 並恢復連線狀態。
- 驗證過去住宿及已退房訂單的未結清款不會被首頁與通知中心排除。
- 驗證收款訂單選單在重新渲染後保持選取，且相關日期與金額摘要會連動。
- 驗證未變更的舊 revision 訂單不會阻擋新付款資料寫入。
- 驗證收款儲存會檢查本機落盤、等待雲端結果並回報失敗狀態。
- 驗證舊衝突佇列不會吞掉新收款，且成功訊息需通過雲端 payment ID 回讀確認。
- 驗證 payments 先於 order_rooms 寫入，且 order_rooms 重複關聯可安全 upsert。
- 驗證線上付款使用獨立 Repository 寫入與 payments 表回讀，不再受整批同步競態影響。
- 驗證未來住宿不會因 lifecycle 狀態而被誤標為逾期。
- 驗證收合訂單卡片直接呈現住宿日期。
- 驗證退房日 11:00 前後會正確切換一般待收款與逾期未結清。
- 驗證叫車日期自動連動入住日期，且有效早餐／叫車安排會出現在首頁服務待辦。
